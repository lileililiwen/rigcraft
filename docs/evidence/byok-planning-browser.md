## Journey exercised

1. Opened `/recommend` with no key: the live status announced the snapshot load, and
   section 2 showed `No key configured` with the parse action disabled and the reason
   `Enter your own provider key to use the assistant.`
2. **Keyboard only** from the top of the page: Tab reached the skip link, brand, three
   navigation links, the snapshot select and the provider key field (7 presses). The key
   was typed, then Tab to the URL (`http://127.0.0.1:8799/ok/v1`), Tab to the model
   (`loopback-mock`), Tab past the part-list opt-in (left unticked), Tab to the sentence,
   typed `Build a $2000 USD gaming PC from my stock and keep FIX-R-CPU-A.`, Tab to the
   consent box, Space, Tab to **Interpret sentence**, Enter.
3. The proposal appeared and focus moved to `Proposed request — review and confirm`. The
   live region announced `Proposal ready with 0 items to confirm. Review every field
   before confirming.` The panel stated `Sent: your sentence, currency, allowed use
   cases; no inventory record.`
4. Read the sources: budget and use case and kept part from the sentence with their
   excerpts, currency from the snapshot, the exclude list a default. Tab into the budget,
   Ctrl+A, typed `1500.00`: the source line added `· Edited by you`.
5. Tab to **Confirm and apply to the form**, Enter. The live region announced `Request
   applied: budget 1500.00 USD, gaming, 1 locked and 0 excluded. Press Generate
   recommendations to run the deterministic search.` Focus moved to the generate button;
   the form showed the same values and `1 locked`.
6. Enter: the deterministic engine ran and returned three compatible options
   (1,063.00 / 813.00 / 1,103.00 USD, 32 valid builds from 96 combinations) with the
   locked CPU at zero incremental cost.
7. Changed the provider URL to `http://127.0.0.1:8799/fail/v1` and interpreted again: the
   alert `The assistant could not interpret that` appeared, focus moved to it, the code
   was `ai_provider_error` and the message `The provider returned HTTP 500.` The sentence
   and every form value were still present, the previous results were still shown, and
   both **Retry interpretation** and **Continue without AI** were offered.
8. Changed the URL to `http://127.0.0.1:8799/ambiguous/v1`, which replies with a budget
   (`$9000`) that is not in the sentence. The budget field was empty with
   `! Needs confirmation — The budget was not traceable to the sentence.` and the
   `Needs your confirmation (1)` block named `budgetMinor`: an untraceable value is
   never used.
9. Reloaded the page: the key field was empty again (state was memory-only), `No key
   configured` returned, and the browser had no `localStorage`, `sessionStorage` or
   cookie entries. Tab to **Continue without AI**, Enter: focus moved to the budget field
   and the live region said `Continuing without AI. The deterministic form needs no key.`
   Typing `900` and pressing Enter produced the honest budget no-solution; typing `1500`
   produced three compatible options. Both ran with no key at all.
10. Repeated the panel, proposal and results states at 390×844.
    `document.documentElement.scrollWidth === clientWidth` (390) in every state, and no
    element extended past the viewport.

- The whole parse → edit → confirm → generate path used no pointer gesture.
- The panel uses native inputs, a native select and native `<details>` disclosures for
  the kept and excluded part pickers.
- Status is symbol plus text: `✎ From your sentence`, `▣ From this snapshot`,
  `≡ Default`, `! Needs confirmation`, plus `· Edited by you`. Colour is never the only
  cue.
- The key input is `type="password"`; the key text never appears in the page body.

## Privacy review

- The sentinel key appears in no HTTP response body, no response header, no service log
  line, no SQLite page and no export. `tests/ai_planning_api.rs` asserts the first four
  through a real request, and `tests/ai_secret_hygiene.rs` scans the committed source.
- Service log (4 lines over the whole session): startup, two `ai interpretation
  requested` records (`operation`, `inventory_records` only) and one Tower HTTP
  `response failed … status code: 502 Bad Gateway`. `grep` for the key, the sentence,
  `loopback-model`, the provider port and `FIX-R-` in the log returned 0 matches.
- Provider stub log: 0 bytes. The stub suppresses its own request logging, so no path or
  header was written.
- SQLite: tables are `snapshots`, `records`, `previews`, `check_reports`,
  `recommendations`; `PRAGMA user_version = 3`. There is no AI table or column, and the
  key string is absent from the database and WAL bytes.
- Browser after the session: `localStorage` and `sessionStorage` have no keys, the cookie
  jar is empty, and the key input holds an empty value after reload.
- Both exports of the generated recommendation (JSON 134,691 bytes, Markdown 7,752
  bytes) contain no key.
- Snapshot totals stayed at 13 records / 26 units / 3,934.00 USD; generating a
  recommendation writes reports only and never reserves stock.
- No inventory record, price or specification left the machine: the part-list opt-in was
  left unticked and the response reported `no inventory record`.
- Screenshots show a masked key field, synthetic fixture rows and local identifiers only.

## Reproduction caveats

- The deterministic recommendation journey this panel feeds is now asserted on every
  run (`e2e/recommendation.spec.ts`, `e2e/keyboard-responsive.spec.ts`). The panel
  itself is not driven by the checked-in suite because it needs a provider key or the
  loopback stub; `AssistantPanel.test.tsx`, `tests/ai_planning_api.rs`,
  `tests/ai_provider_transport.rs` and `tests/ai_secret_hygiene.rs` remain its coverage.
  The captures above were made with Chrome DevTools MCP and remain the visual record.
  See `docs/evidence/browser-suite.md`.
- The 20-second timeout path is proven by `tests/ai_planning_api.rs`
  (`provider_failures_are_stable_codes_without_the_response_body`, HTTP 504) and the fixed
  adapter timeout, not by waiting 20 seconds in the browser. The browser capture shows
  the same failure surface with a provider HTTP 500.
- Evidence is bound to the revision named above. Re-run the commands after any change to
  the panel, the grounding rules, the prompt contract or the API before reusing these
  captures.
